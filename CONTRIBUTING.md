# Contributing

Thank you for your interest. Replications, new methods evaluated against the same ablation truth, bug reports and
documentation fixes are all welcome.

## Set up

```bash
git clone https://github.com/natiixnt/flyvis-circuit-bench && cd flyvis-circuit-bench
uv sync                 # Python 3.11 to 3.13, results path only (numpy, scipy, matplotlib)
make check              # ruff + pytest
```

With the measurement package (`uv run fcb download`), `make reproduce` checks that the published
tables are recomputed byte for byte.

## Ground rules

- **Do not change published numbers by hand.** `results/results.json` and `docs/results.md` are generated by
  `fcb reproduce`; a change of the analysis that changes a number must say so in the pull request and in
  `CHANGELOG.md`.
- **Preregistered rules are fixed.** New analyses are welcome as clearly labelled exploratory additions; they do
  not replace the confirmatory decisions in [docs/preregistration.md](docs/preregistration.md).
- **Adding a method.** See [below](#add-a-method-to-the-leaderboard).
- **Tests.** New code comes with tests that run without the measurement package (synthetic data, see
  `tests/conftest.py`). CI runs `ruff check .` and `pytest` on Python 3.11, 3.12 and 3.13.
- **Style.** `ruff` with the settings in `pyproject.toml`; type hints for public functions; plain ASCII hyphens in
  text.

## Add a method to the leaderboard

1. Write code that gives each of the 604 connection classes of each trained model 000-009 a score (larger = more
   important, the class order of the package files) **without** using the ablation effects. What the package
   offers a method is in `flyvis_circuit_bench.score.method_inputs`; methods that need activations or gradients
   load the flyvis models (`uv sync --extra measure`).
2. Save the scores (`numpy.savez("scores.npz", **{model_id: scores})`) and run
   `uv run fcb score --data data/measurements-v1.0.0 --scores scores.npz --name "your method" --cost "what it needs"`.
3. Open a pull request that adds the printed row to the Leaderboard tables of `README.md` and `README.pl.md` (in
   AUROC order) and links the code that produces `scores.npz`. Say what the method needs (connectome only,
   weights, forward or backward passes) and whether it was tuned on these models.

We accept a row when we can rerun your code and get the same `fcb score` output. Methods tuned on the ablation
truth of these models are welcome as a separate, clearly marked row, not in the main ranking. Our own rows are
generated by `fcb reproduce` (`report.leaderboard_table`) and are not edited by hand.
